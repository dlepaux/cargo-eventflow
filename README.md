# cargo-eventflow

[![CI](https://github.com/dlepaux/cargo-eventflow/actions/workflows/ci.yml/badge.svg)](https://github.com/dlepaux/cargo-eventflow/actions/workflows/ci.yml)
[![Crates.io](https://img.shields.io/crates/v/cargo-eventflow.svg)](https://crates.io/crates/cargo-eventflow)
[![License: MIT OR Apache-2.0](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](#license)

Auto-derive event-flow diagrams from Rust source for NATS-based
systems. Walks a Cargo workspace, extracts publish/subscribe call
sites, resolves subject patterns, and emits a Mermaid diagram of
the event flow.

> **Status:** `0.0.x`. The analyzer + emit pipeline works end-to-end;
> `cargo eventflow mermaid` and `cargo eventflow json` are wired
> against the public lib API. `check` (CI drift gate), `init`
> (auto-detect config), `dot` / `d2` output, and `--explain`
> resolver tracer are on the v0.2 roadmap.

## What problem this solves

NATS-based Rust systems lose their event topology in code within
months. Subjects are string-formatted at call sites, durable
consumer names are passed at boot, and the only place the full
publish/consume graph exists is in the operator's head — plus,
sometimes, a hand-drawn Mermaid diagram somewhere in `docs/` that
goes stale on the next refactor.

`cargo-eventflow` is the missing executable contract: **the
diagram is generated from the AST**, and (once `check` ships in
v0.2) CI fails if the committed diagram drifts.

## Why static analysis instead of annotations

Doc-comment annotations (`@publishes foo`) are tempting but have a
fatal flaw: **they don't validate**. You write
`@publishes foo.bar`, refactor publish away, annotation stays.
Same drift you wanted to escape from hand-drawn diagrams. No gate
catches it.

AST extraction can't drift — regenerated each run from the actual
code. Catches inconsistencies for free (publisher without consumer,
consumer without publisher). Doc-comment annotations stay in the
toolkit as the **escape hatch** for the small percentage AST can't
recover (macros, runtime-bound subjects, ingress/egress on
functions).

## Quickstart

While the tool isn't on crates.io yet:

```bash
cargo install --locked --git https://github.com/dlepaux/cargo-eventflow
cd your-workspace        # any Cargo workspace using NATS + a typed-subject convention
$EDITOR .eventflow.toml  # see examples/ for a starting point
cargo eventflow mermaid -o docs/event-flow.md
```

Output is a Mermaid diagram embedded in a Markdown code fence. The
`@generated by cargo-eventflow (format: mermaid-v1)` banner is a
Mermaid `%%` comment so the file is valid input for `mmdc`, Mermaid
Live Editor, VitePress, GitHub Markdown preview, and any other
renderer that consumes either a `.md` file or raw Mermaid.

## Configuration

`.eventflow.toml` at workspace root. Minimum viable file:

```toml
[bus]
[[bus.publisher]]
kind = "trait"
path = "my_bus::Publisher"
method = "publish"

[[bus.consumer]]
kind = "trait"
path = "my_bus::Consumer"
method = "subscribe"
```

Full annotated reference: [`examples/generic.toml`](examples/generic.toml).
A real-world example covering trait + inherent methods (outbox
publishers), helper crates, free-function subject builders, and
explicit ingress/egress declarations:
[`examples/gordon.toml`](examples/gordon.toml).

## Output format

`graph LR` Mermaid with:

- **Ingress trapezoids** for declared external data sources
- **Service rectangles** for workspace member crates
- **Subject stadiums** for resolved NATS subject patterns
- **Egress trapezoids** for declared external sinks
- **Publisher-grouped subgraphs** when one service is the sole
  publisher of a subject; **multi-publisher** cluster otherwise
- **Per-edge `linkStyle`** directives for renderer compatibility
- **Theme system**: `default` / `high-contrast` (WCAG AA-ish) /
  `monochrome` (stabilises diffs across renderer environments)

Dynamic segments render as `*` (single segment) or `>` (tail
wildcard). Fully-unresolvable expressions render as `?` plus a
diagnostic — honest fallback over silent omission.

## Stability

Format version + tool semver promises live in
[STABILITY.md](STABILITY.md). The short version: format version
(`mermaid-v1`) is stable for the `0.x` lifetime; breaking format
bumps go to `mermaid-v2` with one minor cycle of dual emit. The
`@generated` banner stamps the format version but not the tool
version by default — patch / minor upgrades do not force every
adopter to re-commit their checked-in diagram.

## CI integration

Once `cargo eventflow check` ships in v0.2 you'll be able to
gate CI on diagram drift the same way `cargo fmt --check` gates
formatting drift. Today: regenerate locally and commit; reviewers
see the diagram diff in PRs.
